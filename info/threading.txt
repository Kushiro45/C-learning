threads are used for parallelism. are powerful but one needs to use synchronization mechanisms to protect the integrity of data.
one way for parallelism is using processes.
1) They take TIME to create: a few miliseconds but its inefficient
2) Hard to share data: forks are copy of original, to send data back, establish a pipe or something
3) Hard to create as well.

solution: threads.
Threads are nonblocking unlike processes, so even if one threads gets blocked for I/O orsomething else, other threads can keep working.

Requirements: POSIX thread library or pthread.
the functions that are going to be threaded should have void* return type. since void pointers can point to any data in memory.
its safe to say one program will atleast have two threads XD. 

CREATION:
pthread_t t0; ---> records all information about the thread.
pthread_t t1;
/* t0 is basically a thread descriptor but since different OSes have different implementation we are using pthread_t instead of int like in socket*/

/*create threads with pthread_create() syscall*/

if(pthread_create(&t0, NULL, function_name, NULL) == -1) 
syntax:
pthread_create(&storethreadID, threadattributes, function, funargs)
thread attributes lets customise things like stack size, priority, scheduling policy

if(pthread_create(&t1, NULL, func2, NULL) == -1)
	error("Cant create thread t2");

then you need to wait for the thread to finish before the program exits
	pthread_join(t0, &result)
result is a void pointer that stores the return val of each function.


now obviously when dealin with threads that are working with the same data, we need to have mutexes (Mutual exclusion so that only one thread writes or reads from the data)
